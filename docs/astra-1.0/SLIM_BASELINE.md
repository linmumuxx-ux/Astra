# Astra 1.0 瘦身基线

本文是 **1.0 的产品范围基线**。实现现状仍以 `architecture.md` 为准，实施清单仍只有 `openspec/changes/rebuild-astra-1-0/tasks.md`。与本文冲突时，以本文的「在范围内 / 不在 1.0」为准；历史设计包不再充当完成门禁。

历史设计包（未纳入仓库的 `Astra_1.0_全新架构与产品交互设计.md` 等，指纹见 `baseline.json`）要求按全部章节、全部页面和全部门禁同时验收。该包整体过宽。1.0 保留硬边界，把产品完成收成一条垂直切片。逐条差异见 `SCOPE_DIFF.md`。

## 1.0 完成定义

下面七步在**同一条真实链路**上跑通，即 1.0 Done。分项演示不能互相代替。

1. **Human↔Employee 长期私聊。** 消息持久、成员 ACL 生效；投递不等于已读或已处理。
2. **Inbox / Routine 唤醒。** 到期 Routine、私聊或外部来源进入 Inbox；短 Persona 决策由后端校验后执行。观察与处理结论分开提交。
3. **创建 Task。** 业务主责是 Employee。Task 保存目标、原始验收标准和闭环状态。
4. **Worker 用 OpenCode 执行。** TaskExecution 只索引 Worker、原生 Session、Workspace、尝试、终态和证据。原生消息不复制成第二套 Transcript。
5. **独立验收。** Worker 自报完成不能把 Task 标为完成。人类或另一名员工按证据逐条复验后才闭环。
6. **一张风险写入的人类批准卡。** 写入要同时通过 Role 上限、该员工的工程授权，以及这一次人类批准。批准绑定目标版本、策略版本和有效期；批准不等于已经执行。
7. **新应用路径不再暴露旧运行入口。** `apps/*` 与 `domains/*` 是目标运行树。新路径不提供 0.xx 业务 API，也不把 `backend/`、`frontend/` 当作新应用的启动入口。删除这两棵树是切换之后的任务，不在本阶段执行。

切片之外的页面可以继续存在。页面存在、单测通过或分项 live 报告，都不等于上面这条链已经关闭。

空间表现用状态驱动的 2.5D / DOM 即可。正式 Three.js WebGL 三维首页不是 1.0 门禁。

## 硬边界（保留）

这些规则不因瘦身放宽。

| 边界 | 1.0 要求 |
| --- | --- |
| Employee ≠ Worker | Employee 是岗位与业务身份，不绑定固定主机。Worker 是执行资源，不承担岗位人格。 |
| 来源与关注分离 | SourceEvent 只引用来源。InboxAdmission 保存关注关系。观察、处理、终态各是各的事实。 |
| 主责与执行分离 | Task 的业务主责是 Employee。执行事实在 Worker / TaskExecution。 |
| 独立验收 | Worker 的完成声明不是完成。验收必须依据原生证据，由独立主体作出。 |
| 无业务兼容层 | 不保留 0.xx 业务 API 兼容层。旧数据只允许一次性迁移工具，工具不进入在线业务路径。 |
| 单一运行树 | 目标是 `apps/*` + `domains/*`。旧 `backend/`、`frontend/` 仅作复制来源，直到切换后按计划删除。 |
| 轮次隔离 | 取消、重试、人工确认、超时、断线与恢复都要保证旧轮次不能覆盖新轮次（`superseded_by`）。数据库行锁内不做 OpenCode、SSH 或网络 I/O。 |
| 写入三道门 | 风险写入至少是 Role 上限 ∩ 员工工程授权 ∩ 人类批准。已实现的更严检查可以保留，但不得绕过这三道。 |

执行语义以 OpenCode Server / Session / Event 为准。不另起 DeepSeekBot、Grok、OpenClaw 隐喻下的第二套运行时。

## 在 1.0 范围内

- 人类与一名员工的长期 DM，以及这条 DM 触发的 Inbox。
- Routine 到期唤醒，以及 Persona 的有限决策（回复、记一条、建 Task、请人批准、提交验收）。
- 创建 Task、绑定 Worker、OpenCode 原生执行、证据索引。
- 人类或独立员工按证据验收。
- 一条具体风险写入的批准 / 拒绝卡，含版本与有效期复验。
- 新 `/api/v1` 与 `apps/web` 只走新运行树；文档写明旧树的删除计划。
- 状态驱动空间（2.5D 或等价 DOM）能进入上述 DM 与任务。二维降级可以保留，不单独立项验收 WebGL。

## 不在 1.0（Post-1.0 / 可选）

下列能力可以留在代码或页面里，但**不是 1.0 完成条件**。未做完不得用来阻止切片关闭，也不得假装已经关闭。

- 正式 Three.js WebGL 三维首页，以及把它当作空间门禁的 2D 降级 / 减少动态 / 离线大资源验收。
- 企业 IM 渠道 Binding、受控附件、订阅与通知偏好。
- Skill 的提案 → Worker 验证 → 审批 → 发布 → 观察 → 回滚整条产品。
- 治理成本看板、模型 API 网关硬配额、外部副作用总账，作为发布阻断项。Persona 回合预算若已能阻止未知用量被当成零，可以保留，但不代替网关硬配额，也不列为切片门禁。
- 五层策略全量交集。1.0 只把门禁收成 Role 上限 ∩ 员工工程授权 ∩ 人类批准。
- 「全部页面 + 原设计全部验收门禁同时变绿」。组织调岗与责任清点、Goal 运营指标、团队 Channel 全交互、图书馆全流程、多员工并行与跨岗复验，都属此类。
- 超出 OpenCode 的隐喻型运行语义。
- 公司环境全量 ETL 切换：真实旧库与 Session / Workspace / 知识 / Skill 逐类签收、公司 Linux 全服务部署、切换后删除 `backend/` 与 `frontend/`。一次性迁移工具继续单独存在，供日后使用。
