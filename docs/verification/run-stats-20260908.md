# 任务记录统计区优化

- 新增 `GET /api/runs/page`，返回 items/page/page_size/total/stats；旧 `/api/runs` 保留兼容其他调用方。
- 全部筛选（搜索、员工、分类、统一状态、重试、创建日期）在 SQL 聚合及分页前应用；日期沿用此前 created_at 的 UTC 日期口径，结束日期包含当天。
- 成功率仅包含 COMPLETED/PASSED 与 FAILED/BLOCKED/TIMEOUT/LOST；无完成或失败时显示 —。平均时长仅包含 started_at 和 finished_at 均非空的记录。
- Token 累计实际 total_tokens；全无上报显示 —，实际零值保留 0。
- 一个容器展示执行次数、成功率、平均时长、Token；失败、重试、等待输入、关联任务为轻量二级指标。只对可筛选数字添加按钮。
- 页码独立于统计；筛选及页大小改变回到第一页；使用请求序号防止旧响应覆盖新筛选。任务标题随分页记录返回。

验证：后端专项及 API 回归 9 passed；Ruff、Vue 类型检查与生产构建通过；Chromium 统计/分页/筛选交互专项 1 passed；git diff --check 通过。构建仍有既有大 chunk 提示。

本地 8100 后端已重启加载新接口。真实数据验证：20 runs、15 tasks、13 completed、7 failed、65% 成功率，page_size=1 的第 1/2 页统计相同。浏览器真实页面正常加载。MySQL 时长使用 TIMESTAMPDIFF(MICROSECOND)，本轮未连接公司 MySQL 验证。
