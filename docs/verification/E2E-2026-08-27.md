## E2E 功能覆盖

浏览器测试使用临时 SQLite 数据库、隔离端口和可控 OpenCode 测试替身，验证：

1. 总览从真实 API 加载，并展示 V0.2 今日 Token 与工具调用指标。
2. 数字员工、任务中心、运行记录、人工介入和配置中心均可从主导航访问。
3. 手工任务可创建、暂停、继续，状态和事件证据与 API 一致。
4. 员工详情可追溯默认执行环境、实际 Token 趋势和工具 Top。
5. 任务详情按所有 Run 汇总实际 Token、模型与工具明细。
6. Run 可进入独立详情，查看环境快照、模型、Token、工具与 Session。
7. 可从管理台创建新员工，并分项检测本地 OpenCode 与 Workspace，环境变为 `AVAILABLE`。
8. `WAIT_HUMAN` 任务可补充上下文并恢复为 `READY`。

机器可读结果：`artifacts/test-results/results.json`；HTML 报告：`artifacts/playwright-report/index.html`。运行产物被 Git 忽略，可用 `./scripts/e2e.sh` 重建。

## 后端覆盖重点

- 员工必须启用、允许自动领取且环境为 `AVAILABLE` 才能领取任务；
- 领取时保存 Task 环境快照，Run 再固化同一快照；
- 远程任务使用远程 Workspace 路径，不误用本地证据控制目录；
- OpenCode JSON 事件只按实际字段采集 Token 与工具调用；
- 首次失败后恢复原 Session，失败和成功 Run 的用量均保留；
- Verifier 真实运行命令，缺少可程序化验证条件时拒绝完成；
- V0.1 临时库经 Alembic 升级后数据结构与回填符合预期。

## 部署检查

- Compose 文件可被标准 Compose v2 使用；后端启动时执行 `alembic upgrade head`。
- 后端镜像已包含 Linux `openssh-client`，便于远程环境检测和执行。
- 当前验收主机未安装 Docker CLI，因此容器实际构建和目标 Linux SSH 连通性不在本机自动化结果中；需按《部署手册》在部署环境完成上线验收。
- 正式 `nr_test_system` 接口仍需对端联调。

## 非阻断提示

- Python 3.14 下 FastAPI/httpx 与 pytest-asyncio 发出弃用警告；生产镜像使用 Python 3.12，本次功能不受影响。
- ECharts 主包使单个前端 chunk 接近 500 kB；不影响功能，可在后续版本进行分包优化。
