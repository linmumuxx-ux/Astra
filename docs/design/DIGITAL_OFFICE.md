# 数字办公室设计说明

更新时间：2026-08-28

## 目标

数字办公室需要同时回答三个问题：

1. 不同岗位的员工分别在哪里；
2. 每名员工此刻处于什么状态；
3. 他正在做什么，是否需要使用者处理。

## 参考案例

### Gather Virtual Office

- 官方页面：<https://www.gather.town/>
- 功能说明：<https://www.gather.town/features>

Gather 的有效做法是把成员放入可识别的团队区域，并通过人物、位置和状态让使用者快速感知“谁在线、谁忙碌、谁可以交流”。Astra 借鉴“团队区域”和“一眼看见工作状态”，但不采用像素游戏地图或自由移动机制，以免削弱任务管理效率。

### Microsoft 365 Profile Cards

- 官方说明：<https://support.microsoft.com/en-us/outlook/profile-cards-in-microsoft-365>

Microsoft 365 人物卡以头像和姓名建立身份，再分层展示岗位、可用状态和组织信息。Astra 借鉴“头像优先”和“点击后展开更多信息”的信息层级，把任务、进展和用量放在人物身份之后。

## Astra 的落地方式

- 按员工岗位自动形成区域；相同岗位员工进入同一区域，不需要管理员额外维护区域。
- 岗位区域使用稳定但不同的强调色，显示成员数和当前工作状态摘要。
- 员工使用由 ID 稳定生成的差异化数字肖像，包含面貌、发型、耳机和在线状态灯；员工数量增加时无需新增图片文件。
- 卡片使用“正在专注工作”“有一个问题想问你”“今天状态不错”等近况表达，并展示真实任务标题和最新进展。
- 今日完成、Token 和工具调用保留为辅助信息，不替代员工身份和当前工作。
- 点击卡片后展开详细工作现场，继续提供员工详情和任务详情入口。
- 保留减少动效设置，并为窄屏提供单列布局。

## 验证

Chromium E2E 会验证：

- 测试平台开发、自动化、防线运营分别形成岗位区域；
- 员工卡片存在人物肖像；
- 工作中员工显示拟人化近况；
- 任务进展、今日完成和详情入口仍然可用。
