# 数字办公室设计说明

更新时间：2026-09-05

## 唯一视觉基线

首页以已确认的薄荷绿数字办公室效果图为唯一视觉基线。视觉关键词固定为：通透、明亮、冷白、薄荷绿、轻拟真 2.5D、连续空间。页面不再使用深色游戏地图、像素风、暖木色办公场景，也不把员工卡片网格或数据看板作为第一视觉。

办公室建筑壳只承载墙面、窗景、地面与空间纵深；团队标识、办公岛、工位、员工、状态气泡和交互层全部由 Vue DOM 与 CSS 渲染。完整办公室背景图不参与首页排布。

## 页面结构

首页固定为以下四层：

1. `TopNavigation`：全站顶部导航、全局搜索、刷新、连接状态、待处理角标与管理员入口；
2. `OfficeSummary`：NEXUS 标题、轻量状态统计与团队锚点；
3. `DigitalOffice`：连续办公室、团队区域、办公岛、固定工位、员工与公共区域；
4. `ActivityBar`：单行最近动态，链接到运行记录。

主导航不再使用左侧栏。首页使用浏览器主滚动条，不在办公室内部创建第二套纵向滚动。

## 办公区与工位

- 员工按岗位与任务分类自动归入自动化工程、测试平台、防线运营等团队区域；未知团队使用稳定的回退名称。
- 团队区域存在于同一连续空间中，不使用带底色和边框的业务卡片容器。
- 每个团队按 2、4、8 人办公岛组合；1–2 人生成 2 座岛，3–4 人生成 4 座岛，之后以 8 座岛搭配必要的 4 座岛。员工按创建时间与 ID 稳定排序，因此刷新与状态变化不会改变工位。
- 工位、桌面、屏幕、椅子与人物都是可独立缩放的 DOM 图层；人数增长只增加办公岛，不引入坐标模型、寻路或自由移动。
- 会议区、白板、休息区和绿植只负责空间节奏，不承载业务状态。

## 员工与状态

- 人物使用当前 NEXUS Q 版坐姿精灵图集，默认只展示人物、姓名和状态点。
- 悬停/聚焦时显示姓名、当前状态、运行时长与当前任务；点击后打开右侧详情抽屉。
- 搜索会定位并高亮匹配员工，团队锚点滚动到对应区域。
- 页面最多同时显示 5 个状态气泡，且只对异常与等待人工状态常驻展示；正常员工、搜索命中和最近完成都只通过姓名状态点、聚焦态或悬停详情表达。
- 业务色只表达状态：工作中为绿色、空闲为灰色、等待人工为橙色、异常为红色。团队牌统一使用薄荷绿。

## 技术边界

- 视图层只使用 Vue、DOM、CSS、PNG 与 SVG 图标。
- 不使用 Three.js、Pixi、Canvas 游戏循环、人物自由移动、路径查找或区域坐标模型。
- 复用现有 `Employee`、`Task`、`Run`、Event 与单一 SSE 数据链路；办公室通过适配器把真实业务状态转换成视觉状态，不新增办公室后端模型。
- 右侧抽屉、平台助手、顶部导航和强提醒使用明确的层级，避免相互遮挡。

## 验证基线

Chromium E2E 覆盖：

- 连续办公室、顶部导航、搜索、团队锚点、员工详情抽屉和整页滚动；
- 真实 5 人（自动化工程 3、测试平台 1、防线运营 1）以及 20、40、60 名员工时的办公岛组合、固定排序与无横向溢出；
- 等待人工和异常员工的强提醒，以及全局最多 5 个气泡；
- 任务开始、完成、刷新和 SSE 重连时工位坐标不漂移；
- 1440、1920、2560 桌面宽度与窄屏布局。
