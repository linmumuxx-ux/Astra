## Context

已有 TaskReview 租约和 TaskSummary 单任务唯一约束，但复盘没有调度入口；员工 MCP 与助手都可写候选。知识服务有内容指纹、证据、人工发布和 Wiki 检索，无需新增存储或检索服务。

## Goals / Non-Goals

目标：接通人工完成到后台复盘的闭环，减少重复经验，核实证据并可观察重试。
非目标：重建执行状态机、自动发布知识、删除或批量重写历史知识。

## Decisions

- Task 人工完成状态为调度依据；确认时用原生主会话消息同步终态，不把业务成功冒充执行成功。复用现有 Celery Beat/control 队列周期调度。
- 保留现有轮次 ID 和 TaskReview 记录以保护历史幂等；任务锁内只核对状态及写结果。读取原生证据、检索与助手网络调用均在锁外，提交时再次核对轮次与 superseded_by。
- 经验提炼、语义比较由现有复盘模型完成；增加可查询候选/正式经验的只读工具，提交可指定合并目标及理由。服务端以全局内容指纹兜住完全重复，以知识行锁和现有唯一约束保护并发。
- 候选可合并正文并保留证据；正式知识只追加证据，不被模型改正文。候选正文改变后撤销既有验证标记。验证引用必须来自实际完成的工具结果或明确人工验证，其他真实消息只作为未验证依据。
- 总结与候选原子保存，复盘错误或租约到期可复用原记录重试；任务详情共用复盘读取函数，前端手动刷新，不引入额外轮询。
- 停用员工提交及基于任务成功的批量验证流程；保留已有数据字段用于历史展示，不做破坏性删表或字段迁移。

## Risks / Trade-offs

- 语义匹配受模型判断影响：要求检索和合并理由，保留人工审核与全部引用证据；精确重复由数据库保护。
- 外部 Session 不可达：报告复盘失败并重试，不猜测、不影响任务完成。
- 发布后的正文补充仍需人工编辑审核；自动化只补充可核实证据，保护正式知识。
