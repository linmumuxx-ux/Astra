# API 中转第一阶段设计

## 边界和部署

控制面使用现有 FastAPI/SQLAlchemy，数据面新增独立 ASGI 进程 `app.gateway.server:app`，绝不把模型长连接放入主 Backend。下游 Proxy 继续负责 Token 获取、刷新和协议适配。Gateway 只支持下游 OpenAI 兼容接口；首批入口为 `/v1/models` 和 `/v1/chat/completions`，其他协议需后续单独设计。Gateway 作为独立进程运行，默认只监听内部地址 `8110`，不直接对外暴露。开发环境下 Vite、正式环境下 nginx 都以与管理台/后端同域的 `/v1` 反向代理到该内部监听，外部客户端经由同域入口调用，无需直连 `8110`。线上至少一台 Gateway，可横向扩展；Redis 是跨实例运行态和配置通知的共享依赖，Redis 不可用时新请求拒绝并给出结构化 503，不能退化到进程内并发/额度计数。

## 数据与安全

MySQL 表：`gateway_nodes`、`gateway_pools`、`gateway_routes`、`gateway_keys`、`gateway_config_versions`、`gateway_requests`、`gateway_health_checks`、`gateway_audit_events`。节点所属 Pool 和支持模型显式保存；路由模型名唯一，第一阶段一个路由指向一个 Pool。节点密钥以主密钥加密后入库，密钥和主密钥不得进入响应或日志。Gateway Key 以 `agw_` 前缀生成，仅创建时返回原文；库中只存不可逆摘要和短前缀。主密钥缺失时拒绝管理密钥与节点凭据相关操作，生产启动须强制校验。日志只存元数据，不存 Prompt、Authorization 或原始响应体。

Key 吊销独立于配置发布：数据面按已发布快照鉴权，而吊销只改草稿，因此需要跨实例共享阻断。控制面先把 Key 摘要追加写入 Redis 阻断集合，再提交 DB 吊销；Redis 失败返回结构化 503，绝不谎称成功。数据面在读取请求体与调度之前查询该集合，Redis 不可用或就绪哨兵缺失时 fail closed；已有长流不因吊销或就绪变化断开。就绪状态是同集合内的哨兵成员（`__ready__`），不是独立键：Redis 按 maxmemory 淘汰只能整体删除该集合键，哨兵与摘要一起消失，因此绝不会出现「标记还在、集合已被淘汰」的假就绪。`is_key_revoked` 用同一次原子读取（Redis Lua / 进程内单步）先查哨兵再查摘要：哨兵缺失即让该次读取本身失败关闭，绝不先查哨兵再查集合，避免两次调用之间集合键被淘汰而放行。集合只增不减，`sync_revoked_key_digests` 用一次 `SADD` 把 DB 全部摘要与哨兵加入同一集合，`revoke_key_digest` 只追加摘要、不单独置位；Gateway 启动与后台周期从 DB 追加同步所有 `revoked_at` 非空摘要后即写入哨兵，因此 Redis 清空/重启后可重建阻断列表。已吊销 Gateway Key 的 DB 行是永久 tombstone：`revoke_key` 与回滚都按 Key 行锁串行化，回滚旧快照既不删除其行、也不清除 `revoked_at` 或重新启用；若旧快照包含该 Key，回滚生成的新快照会改为 disabled+revoked 并保留当前吊销时间，因此回滚到吊销前版本也不会让已吊销 Key 复活。

当前 Astra 管理台没有可信的统一登录和角色系统。API 中转控制面使用独立、服务端校验的管理凭据与角色（view/node/route/key/publish/system），不信任浏览器提交的身份 Header。普通 Gateway Key 只可读取自己的用量；管理员凭据由部署环境安全提供，前端通过交互式输入保存于当前会话，不内置在构建产物中。每项写操作写入审计事件，记录 actor、时间、操作、结果及脱敏前后值。

## 发布与运行态

配置表表示草稿；Publish 在事务中校验引用、模型、节点参数及凭据，生成不可变快照和递增版本，提交后写 Redis 当前版本并发布通知。Gateway 启动时加载最近已发布版本，订阅通知并原子替换内存配置；每次请求只读内存配置，不查询 MySQL。若 Redis 通知丢失，以定期版本校验收敛。发布失败不影响当前版本。回滚将历史快照恢复成新版本并同步草稿，保留完整历史。已运行请求持有原配置引用，继续完成；新请求使用新版本。

Redis 维护跨实例租约式并发计数、周期 Token、熔断状态及 Gateway 心跳。租约应有 TTL/心跳及原子获取/释放，进程崩溃后能回收。周期采用 `Asia/Shanghai` 自然小时和自然日；配额基于已完成请求的实际 `usage` 原子计入，未知 usage 记为 unknown，不估算为零。已有请求绝不因额度变化中断，因并发请求可能产生有限超额，UI 显示实际超额。配置策略：告警、90% 降权、100% 停止新请求、100% 仅记录；默认 80% 预警、90% 降权、100% 停新请求。`DRAINING` 仅阻止新请求，不能取消活跃流。

## 调度与故障

过滤：已启用、调度 `ACTIVE`、健康不是 `UNHEALTHY`、熔断不是 `OPEN`、模型受支持、未满并发、未被额度策略阻止。`UNKNOWN` 节点必须完成一次连接/服务/鉴权/模型/流式探测后才能调度。候选以 least active 为主，结合配置权重、剩余额度、错误率和 TTFT 调整有效权重；选择和并发租约获取要在 Redis 原子化，避免多实例超卖。无节点时区分无路由、无健康节点、池满载和额度超限。连接失败、Connect Timeout 等明确证明请求未发送到下游的情形才可切节点重试；收到响应头或进入流后绝不透明重试。连续 3 次健康失败摘除，2 次成功恢复；被动故障可降级。熔断 `CLOSED → OPEN → HALF_OPEN`，30 秒后允许少量探测，成功关闭，失败重开。

## 转发与指标

校验 Gateway Key 状态、有效期、允许模型与并发后，按路由选节点，并将请求体原样传给同协议下游，仅替换认证 Header。使用流式 HTTP 读取和同步转发 SSE/Chunked，不缓存完整响应；客户端断开时关闭下游并释放租约。成功/失败/取消/超时路径统一终结调用记录。记录 Request ID、Key、模型、Pool、节点、状态码、标准错误码、重试次数、时间、connect/TTFB/TTFT/总时长、输入/输出 Token、TPS、stream interrupted。流式 `usage` 需在结尾由下游提供；无 usage 时标记未知，不能凭字节数伪造。聚合查询按时段计算请求量、成功率、QPS、TTFT p50/p95、总时长 p95、TPS 和 Token 趋势；大流量可逐步加预聚合表，不改变来源语义。

## UI 与运维

沿用 Astra 绿色和已有卡片/表格组件。一级导航进入总览；节点抽屉按基本信息、连接测试、模型探测、限额、Pool、启用顺序配置；详情展示概览、Token、性能、限制、健康、日志、配置。节点默认不直接删除；先 DRAINING 且并发为 0 才允许删除。配置页展示草稿/当前版本/历史，发布和回滚需显式管理权限。运维页展示 Gateway 实例心跳、版本、配置版本、连接数、请求数、错误率及可用的 CPU/内存。开发与正式启动脚本和 systemd 增加独立进程；不在启动时自动发布草稿。

## 验收重点

Mock Proxy 端到端验证普通/流式转发、路由、鉴权、节点故障切换、连接后禁止重试、并发与额度、DRAINING、熔断恢复、发布/回滚及凭据不泄漏。控制面与数据面分别测试，运行态跨两个 Gateway 实例验证原子计数。前端 type-check/build，最后检查完整 diff。
