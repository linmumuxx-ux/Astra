## Context

首页已经使用四个聚合接口，后端负责选择当前未被替代的 Session；管理台仅在进入及手动刷新时读取。已有用户改动包含员工形象持久化与关闭自动刷新，须保留。

## Goals / Non-Goals

目标是首屏看清员工、任务与人工事项，并直接进入已有详情及工作台。不改变业务任务与 Session 状态、不增加接口和轮询、不重建 3D 场景。

## Decisions

- 保留原布景与桌椅人物，降低工位视口起点、缩小横向内边距；工位标签显示姓名、后端状态文案及当前任务，任务入口与员工详情分开。
- 统一顶部统计为在线员工、正在工作、今日完成、待处理，文案明确为快照；只使用已有 overview 值，不从事件或时间推算状态。
- 员工可用状态从 enabled/status 投影；当前轮仍从后端 state 与绑定事实投影。离线、停用不再套用空闲视觉；不把可用状态声称为 Server 实时连通。
- 在展示适配层合并相邻且员工、事件类型、目标、描述一致的动态；保留最新时间、目标与次数，不跨越中间的业务事件，也不改写历史 Event。
- 首页四个请求共享本批 AbortSignal，15 秒超时后释放刷新按钮；卸载时取消请求。各模块保留独立快照时间和错误。
- 首页创建入口直接进入任务页的现有 TaskCreateDrawer，创建、校验、分配与跳转逻辑保持复用。
- 聚合动态在查询阶段排除目标已删除的历史事件，避免失效链接挤占十二条关键事件。

## Risks / Trade-offs

- 手动快照不会自动跟随执行：明确“自动刷新已关闭”和更新时间，持续动效仍停止。
- 四个接口完成时间不同：保留分区时间；部分失败不声称全页已更新。
- 本地 API 目前不可用：先恢复可验证的本地服务；模拟回归和真实环境验证分别记录。
