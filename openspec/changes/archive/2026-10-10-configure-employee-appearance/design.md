## Context

首页使用 `assets/office/characters` 的九个人物、正反面 PNG；员工头像和旧办公室仍使用十二格图集并按 ID 或团队分配。员工模型没有形象字段。

## Goals / Non-Goals

目标是持久保存每位员工的选择，所有员工展示使用同一人物，保留已有首页形象。范围限于管理台已有的新建、编辑入口，不增加上传、素材生成或 Runtime 工具权限。

## Decisions

- 在员工记录增加非空整数 `character_id`（0–8），作为唯一事实源。创建未传值默认 0；PATCH 未传值保持原值，显式 null、越界、字符串、布尔值和小数拒绝。相同形象允许多员工使用。
- 共用九种形象目录与图片地址函数；配置使用正面全身预览，头像使用正面，首页保留既有朝向规则。删除动态避重分配与运行时 ID 映射，避免选择随同事增减而变化。
- 迁移中按现有首页 JS 哈希规则一次性回填，包括 Unicode ID 的 UTF-16 首码元语义。长期代码不保留历史推测逻辑。
- 配置选择纳入现有表单快照、保存及放弃流程。保存失败保留选择，成功后现有刷新读取数据库；形象修改不触发工作环境检测。

## Risks / Trade-offs

- [新增非空字段要求先迁移] → 发布前运行 Alembic；迁移以隔离 SQLite 数据库验证，MySQL 真实环境单独注明验证边界。
- [旧头像素材替换会改变员工管理页外观] → 这是统一首页形象的预期变化，首页原有人物保持不变。
- [回滚丢失用户形象选择] → downgrade 只删除形象列，其他员工字段不变；回滚前备份选择数据。
