# API 中转第一阶段设计

## 边界和部署

控制面使用现有 FastAPI/SQLAlchemy，数据面新增独立 ASGI 进程 `app.gateway.server:app`，绝不把模型长连接放入主 Backend。下游 Proxy 继续负责 Token 获取、刷新和协议适配。Gateway 只支持下游 OpenAI 兼容接口；首批入口为 `/v1/models` 和 `/v1/chat/completions`，其他协议需后续单独设计。Gateway 作为独立进程运行，默认只监听内部地址 `8110`，不直接对外暴露。开发环境下 Vite、正式环境下 nginx 都以与管理台/后端同域的 `/v1` 反向代理到该内部监听，外部客户端经由同域入口调用，无需直连 `8110`。线上至少一台 Gateway，可横向扩展；Redis 是跨实例运行态的共享依赖，Redis 不可用时新请求拒绝并给出结构化 503，不能退化到进程内并发/额度计数。

## 数据与安全

MySQL 表：`gateway_nodes`、`gateway_pools`、`gateway_routes`、`gateway_keys`、`gateway_requests`、`gateway_health_checks`、`gateway_audit_events`。节点所属 Pool 和支持模型显式保存；路由模型名唯一，第一阶段一个路由指向一个 Pool。节点密钥以主密钥加密后入库，密钥和主密钥不得进入响应或日志。Gateway Key 以 `agw_` 前缀生成，仅创建时返回原文；库中只存不可逆摘要和短前缀。主密钥缺失时拒绝管理密钥与节点凭据相关操作，生产启动须强制校验。日志只存元数据，不存 Prompt、Authorization 或原始响应体。

Key 吊销不等待配置刷新：控制面先把摘要追加写入 Redis 共享阻断集合，再提交 DB 吊销；Redis 失败返回结构化 503。数据面在读取请求体与调度前原子查询同一集合中的就绪哨兵和摘要，Redis 不可用或哨兵缺失时拒绝新请求，已有长流继续完成。集合只增不减且没有 TTL；Redis 淘汰整个集合时哨兵与摘要同时消失，不能出现假就绪。启动及后台周期从 DB 同步永久吊销行并写入哨兵，清空后可重建。普通编辑不能清除 `revoked_at`，不再保留版本恢复与 Key 行锁逻辑。

API 中转控制面与 Astra 管理台采用相同的访问边界，不再提供独立管理登录、Token 或角色系统；页面直接加载管理数据并提供操作，删除 `/permissions` 接口和管理会话缓存。部署环境通过内网或统一入口限制 Astra 管理台及 Backend 的访问。删除独立 Key 自助门户及其接口、鉴权依赖和浏览器缓存；用量继续由管理台 Key 列表和调用日志展示。模型数据面继续校验 Key 的状态、有效期、模型与额度。每项写操作继续写入审计事件，记录时间、操作、结果及脱敏前后值；来源固定为 `actor=astra`、`actor_role=system`，不表示经过登录验证的个人身份，不采信浏览器身份 Header。保留历史审计列和历史记录；回退到旧代码时需恢复管理凭据配置。

## 保存与自动刷新

节点、Pool、路由与 Key 表是唯一配置事实源，控制面在各项保存时校验参数、引用及唯一性。允许停用有路由的 Pool，用于停止新请求；新连接仍须通过完整健康探测才能参与调度。删除配置版本模型、草稿校验、发布、回滚、对账接口及 Redis 配置通知。

Gateway 启动和后台按 `ASTRA_GATEWAY_CONFIG_POLL_INTERVAL`（默认 10 秒）从同一数据库读取事务加载四张配置表，原子替换完整内存视图。SQLite 显式开启读事务，MySQL 使用 REPEATABLE READ，避免多个查询混合不同提交的数据。每个请求在入口取得一次配置引用，鉴权、路由和重试均使用该引用；已有请求不因配置刷新中断。数据库读取失败保留最近有效视图，下一周期重试；首次启动失败时保持空配置并拒绝调用。各实例独立读取同一配置表，不维护版本号、发布状态或持久快照。

迁移 `0032_gateway_saved_config` 只删除配置版本历史表，保留已保存配置、吊销行、日志、健康记录与审计。升级后原先尚未发布的保存内容也会被采用，不用旧发布快照覆盖它；部署前核对当前保存配置并备份数据库，同步升级 Backend 与 Gateway。历史删除不可逆，回退旧代码须恢复升级前数据库备份。配置停用与 DRAINING 在实例下次刷新后阻止新调度，删除仍要求 DRAINING 且活跃并发为零；本次不新增即时调度阻断状态。

Redis 维护跨实例租约式并发计数、周期 Token、熔断状态及 Gateway 心跳。租约应有 TTL/心跳及原子获取/释放，进程崩溃后能回收。周期采用 `Asia/Shanghai` 自然小时和自然日；配额基于已完成请求的实际 `usage` 原子计入，未知 usage 记为 unknown，不估算为零。已有请求绝不因额度变化中断，因并发请求可能产生有限超额，UI 显示实际超额。配置策略：告警、90% 降权、100% 停止新请求、100% 仅记录；默认 80% 预警、90% 降权、100% 停新请求。`DRAINING` 生效后仅阻止新请求，不能取消活跃流。

## 调度与故障

过滤：已启用、调度 `ACTIVE`、健康不是 `UNHEALTHY`、熔断不是 `OPEN`、模型受支持、未满并发、未被额度策略阻止。`UNKNOWN` 节点必须完成一次连接/服务/鉴权/模型/流式探测后才能调度。候选以 least active 为主，结合配置权重、剩余额度、错误率和 TTFT 调整有效权重；选择和并发租约获取要在 Redis 原子化，避免多实例超卖。无节点时区分无路由、无健康节点、池满载和额度超限。连接失败、Connect Timeout 等明确证明请求未发送到下游的情形才可切节点重试；收到响应头或进入流后绝不透明重试。连续 3 次健康失败摘除，2 次成功恢复；被动故障可降级。熔断 `CLOSED → OPEN → HALF_OPEN`，30 秒后允许少量探测，成功关闭，失败重开。

## 转发与指标

校验 Gateway Key 状态、有效期、允许模型与并发后，按路由选节点，并将请求体原样传给同协议下游，仅替换认证 Header。使用流式 HTTP 读取和同步转发 SSE/Chunked，不缓存完整响应；客户端断开时关闭下游并释放租约。成功/失败/取消/超时路径统一终结调用记录。记录 Request ID、Key、模型、Pool、节点、状态码、标准错误码、重试次数、时间、connect/TTFB/TTFT/总时长、输入/输出 Token、TPS、stream interrupted。流式 `usage` 需在结尾由下游提供；无 usage 时标记未知，不能凭字节数伪造。聚合查询按时段计算请求量、成功率、QPS、TTFT p50/p95、总时长 p95、TPS 和 Token 趋势；大流量可逐步加预聚合表，不改变来源语义。

## UI 与运维

沿用 Astra 绿色和已有卡片/表格组件。一级导航直接进入总览；节点抽屉按基本信息、连接测试、模型探测、限额、Pool、启用顺序配置；详情展示概览、Token、性能、限制、健康、日志、配置。节点默认不直接删除；先 DRAINING 且并发为 0 才允许删除。仅保留总览、节点、资源池/路由、Key、调用日志五项导航；旧配置版本与自助门户链接回到总览。总览展示 Gateway 实例心跳、软件版本、连接数、请求数、错误率及可用的 CPU/内存。开发与正式启动脚本和 systemd 增加独立进程，启动直接加载保存配置。

## 验收重点

Mock Proxy 端到端验证普通/流式转发、路由、鉴权、节点故障切换、连接后禁止重试、并发与额度、DRAINING、熔断恢复、配置保存后刷新、重启、多实例、刷新失败重试、请求配置隔离及凭据不泄漏。控制面与数据面分别测试，运行态跨两个 Gateway 实例验证原子计数。前端 type-check/build，最后检查完整 diff。
