## Context

SSH、OpenCode Serve 生命周期和图书馆反向隧道已有实现。远程启动检查未识别全局配置；新测试机为 CentOS 7，系统 Git 不支持所需 worktree，Node 官方通用二进制不兼容旧 glibc。

## Goals / Non-Goals

**Goals:** 从保存的员工环境一键安装、配置、启动和验证，并安全重试、重启。提供真实阶段结果与可操作错误。

**Non-Goals:** 不升级操作系统，不删除工程，不复制平台助手配置，不安装数据库/Redis/Docker，不增加运行状态副本。

## Decisions

- 操作使用流式 HTTP 返回阶段结果，SSH 执行有总超时和远端锁；浏览器取消或断线结束当前连接，残留安装命令受超时/远端锁约束。工作环境 `status_detail` 记录操作 ID、截止时间和结果，条件更新隔离旧轮次；过期记录允许显式重试，但不能绕过远端锁。无独立后台作业或任务表。
- 短事务原子预留工作环境，阻止配置修改、删除、检测、任务启动与自动分配；检查占用任务和非终态 Session。网络 I/O 在事务提交后执行。重启同时核查原生 Session 是否忙碌，拒绝停止不属于该目录及端口的进程。
- 依赖安装支持 Debian/Ubuntu、RHEL 系列；CentOS 7 使用独立 Vault 源参数（不覆盖原有 yum 配置）、Node 22 glibc-217 构建和 OpenCode musl baseline，按发布方摘要校验下载。Git 版本不足时编译受验证版本；非 root 无必要依赖时明确提示需管理员安装。
- 全局配置写入 `$XDG_CONFIG_HOME/opencode/opencode.json`，备份并原子合并，仅管理 `astra-gateway` provider、默认模型与 `nexus-library` MCP；保留其他用户配置，遇到现有 JSONC 拒绝覆盖并提示人工处理。工程保持原状，空目录初始化 Git 供独立任务 worktree 使用。
- 中转使用独立员工 Key，摘要保存在既有网关；原始值通过 SFTP 写入权限 0600 的远端配置，重部署校验并复用有效 Key。失败后吊销新建 Key，成功后才替换旧 Key。网关与 MCP 的反向隧道复用进程级持久连接，并在正式 Runtime 连接时重建；既有非托管远程配置不强制接入网关。
- 默认工程目录为 `/opt/astra/projects/astra-02`，仅用于本次测试员工；产品继续使用用户填写的绝对目录。安装版本、npm 镜像、网关地址由部署设置统一配置，表单无需重复填写密钥。

## Risks / Trade-offs

- CentOS 7 构建耗时且归档源可能不可达 → 有界下载、阶段错误、校验摘要、失败可重试；不静默宣称成功。
- 全局配置由同一 SSH 用户共享 → 保留非托管字段，明确展示全局范围；同主机同账号操作串行。
- 本机 Astra 断线会中断隧道 → 重连时重建，Serve 仍只监听回环；远程不保存本机可公开访问的服务地址。
- 配置或安装不是跨机器事务 → 配置备份支持人工恢复，保留已安装依赖；失败后标为不可用，重新检查事实，不恢复/猜测任何 Task 终态。
