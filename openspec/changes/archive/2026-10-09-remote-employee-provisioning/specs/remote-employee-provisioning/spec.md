## ADDED Requirements

### Requirement: 从员工配置部署远程环境
系统 SHALL 为保存了远程地址、SSH 端口、用户名、密码和绝对工程目录的 Linux 员工提供一键部署，安装可运行的 OpenCode、Node.js/npm、支持独立工作树的 Git 及必要依赖，配置 npm 镜像，逐阶段报告实际结果。

#### Scenario: 空机器完成部署
- **WHEN** 管理者为有效远程员工执行一键部署
- **THEN** 系统安装依赖、准备工程、写入配置、启动 Serve 并检查其健康后才报告成功

#### Scenario: 不支持的环境或安装失败
- **WHEN** 系统不支持目标平台、没有安装权限或下载/校验/安装失败
- **THEN** 系统报告失败阶段和可操作原因，环境不可用，允许修复后显式重试

### Requirement: 自动配置模型中转与数字图书馆
部署 SHALL 为远程 SSH 用户配置全局 OpenCode 模型中转和数字图书馆 MCP，使用专属可吊销 Key，不回显 SSH 密码或服务密钥；SHALL 备份并保留现有其他配置及工程内容。

#### Scenario: 自动接入本机服务
- **WHEN** 平台具有可用中转模型和 HTTP 图书馆服务
- **THEN** 远程 OpenCode 可通过受控连接访问中转和图书馆，Serve 仅监听回环地址

#### Scenario: 已有用户配置
- **WHEN** 目标用户已有全局配置或工程内容
- **THEN** 系统备份并合并可支持的配置，保留其他字段和工程；不能安全合并时明确要求人工处理

#### Scenario: 重复部署
- **WHEN** 对已部署员工再次部署
- **THEN** 系统复用有效凭据和已满足版本要求的依赖，不累积有效的重复专属 Key

### Requirement: 安全重启员工 Serve
系统 SHALL 提供远程员工 Serve 一键重启，重启后重新检查健康；SHALL 识别用户全局与工程级 OpenCode 配置，并拒绝终止无法确认归属的进程。

#### Scenario: 空闲环境重启
- **WHEN** 对空闲且已安装配置的远程员工执行重启
- **THEN** 系统重启对应目录及端口的 Serve 并报告实际健康结果

#### Scenario: 活跃执行或端口冲突
- **WHEN** 员工有占用任务、待确认提交、非终态 Session，或原生 Session 忙碌，或端口属于其他进程
- **THEN** 系统拒绝操作并提供原因，不破坏原执行

### Requirement: 操作互斥与中断恢复
系统 SHALL 阻止同一员工的并发部署/重启及操作期间的环境修改、删除、检测和任务启动；SHALL 支持取消、超时、断线后显式重试，旧操作结果 MUST NOT 覆盖新配置或新操作。

#### Scenario: 操作期间再次修改或执行
- **WHEN** 一个环境操作尚在进行且再次部署、修改、删除、检测或启动任务
- **THEN** 系统拒绝冲突操作，界面显示当前阶段

#### Scenario: 取消或断线
- **WHEN** 管理者取消操作、连接中断或操作超时
- **THEN** 系统停止等待并释放所持连接，报告未完成；后续重试仍检查远端互斥和实际健康，不假定已经部署成功

#### Scenario: 旧轮次晚到
- **WHEN** 旧操作在新配置或新操作已生效后返回
- **THEN** 旧结果不得覆盖新环境记录
