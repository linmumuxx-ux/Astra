## Context

首页已有六个 `/api/dashboard/*` 聚合接口、30 秒刷新和单模块错误隔离；App 在首页停用全局 SSE。旧办公室组件含固定坐标、隐藏员工与装饰动画，不适合当前多团队环境。新首页不复用旧办公室布局、人物或背景；按选定参考直接移植开源资源和展示规则。

## Goals / Non-Goals

**Goals:** 首页直接回答员工、真实执行、人工等待与最近动态；工位可达现有任务工作台，布局可扩展且可删除。

**Non-Goals:** 不编排 Agent 内部步骤、不改变任务生命周期、不新增存储、系统或依赖，不修改 workspace-ui。

## Decisions

1. 独立首页组件移植 workbzw 的房间、桌椅、人物资源及分层/锚点，转换为透明 DOM 工位与 CSS 状态动画，不引入 Pixi/Spine 运行依赖；角色稳定分配；团队按后端顺序、员工按创建顺序，状态变化不挪动位置。采用团队/状态筛选与全局搜索控制多员工规模。
2. `Task` 保留业务状态，当前 `RuntimeSession` 通过 `Task.current_session_id` 且 `superseded_by` 为空取得运行事实。当前轮结束时业务 Task 可继续 RUNNING，首页不得继续播放工作动画。现有 presentation 为状态文案事实源，人工原因来自 Task。
3. 复用 App 持有的一条 SSE：首页仅订阅事件及连接状态，事件触发首页聚合刷新；其他管理页保留原有 store 数据刷新。刷新请求合并，刷新中到达事件排队补一次；初始加载、重连与切回前台刷新。每 15 秒有界读取聚合数据弥补 Session 结束不产生业务事件的情况，后台停刷与停动效。
4. 主布局为办公室 + 右侧待人工/动态；顶部仅轻量计数与同步状态。原任务表格移除，图书馆保留简短入口。加载失败保留上一快照并标记过期，初始失败提供模块重试。

## Risks / Trade-offs

- 原生 Session 结束事件不会总写入业务 Event → 已有后台恢复器更新 Session 索引，首页 15 秒补刷，不做逐员工探测。
- 首页接口间非事务快照 → 同批刷新降低偏差；局部失败明确提示，动画依赖当前工位快照有效和 SSE 连接。
- 工位数量增长 → 固定可见房间与内部纵向滚动、团队/状态筛选和桌面网格；全部员工仍可访问。
- 回滚只需恢复首页视图、共享 SSE 首页模式及聚合字段，无数据库迁移。

最终验收范围仅为桌面端（1440/1920），不增加手机/窄屏专用布局。
